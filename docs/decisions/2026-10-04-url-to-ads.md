# Decision brief: URL to Ads by Paneet
Context: A free, open tool that turns a website URL into a short video ad, with first-class Thai support. It is a skill pack that runs inside the user's own AI coding agent (Claude Code / Codex / Cursor), built on HeyGen's open-source HyperFrames (Apache 2.0, v0.8.115 tested). Origin: a hand-built motion pipeline for the "นกโหร" LINE OA mascot proved code-rendered video works; testing then showed HyperFrames already does URL→video but breaks on Thai.

## Decisions (what + why)
- D1: Free giveaway, no login, user pays their own LLM/TTS with their own keys (BYOK) — owner's call after seeing HeyGen's hosted URL-to-Video free tier is capped (watermark, 3 videos/month, needs account).
- D2: Distributed as a skill pack for the user's own AI agent; rendering happens on the user's machine — owner chose this over hosted options; trade-off accepted: Paneet has zero run cost, but only people who use an AI coding agent can use it. A web front can wrap the same engine later without rework.
- D3: Build ON TOP of HyperFrames, not a new engine — HyperFrames already does deterministic HTML→MP4 and URL→video (skill `product-launch-video`); competing with a 53.8k-star free project is pointless. Our value is the Thai layer.
- D4: Scope of the Thai layer = the gaps found in testing (3 Oct 2026):
  - Fonts: all 13 frame presets ship CJK fallbacks, zero Thai anywhere in the repo.
  - Voice: the free offline voice (Kokoro) has no Thai; Thai needs a user key (Gemini / ElevenLabs / HeyGen).
  - Captions: captions.mjs detects sentence ends only from Latin punctuation (`. ? ! , ;`); Thai uses spaces. Intl.Segmenter splits brand names ("นกโหร" → "นก | โหร").
  - NOT broken: Chromium line-breaks Thai at word boundaries correctly; Noto Sans Thai (from npm @fontsource) renders stacked vowels/tone marks correctly.
- D5: Name = "URL to Ads by Paneet", package/repo slug `url-to-ads` (free on npm as of 4 Oct 2026) — owner: putting "Paneet" first reads as hard-sell and people won't want to use it.

## Rejected alternatives (and why)
- Own rendering engine — duplicates HyperFrames, which is free and bigger.
- Hosted web app, render on Paneet's server — Paneet pays render compute for every clip (our 15s test took ~13 min to render) and would hold other people's API keys.
- Web app rendering in the user's browser — hardest to build, very slow on phones.
- Selling it only as a paid service (earlier decision, now overridden by D1).
- Names: "Paneet Short Ads", "Paneet URL to Ads", "@paneet/hyperframes-thai", "paneet-thai-video".
- Using HeyGen's hosted URL to Video — watermark, quota, login.

## Constraints (must / must not)
- Must: no login, no Paneet account, no Paneet server in the loop. Keys belong to the user and never leave their machine.
- Must: "by Paneet" appears wherever the name appears (README title, repo description, install output). "URL to Ads" alone is a generic phrase.
- Must not: put Paneet branding or watermarks into the user's generated videos.
- Must: keep HyperFrames' Apache 2.0 LICENSE/NOTICE obligations.
- Must not: publish to npm, make the repo public, tag a release, or open PRs/issues on heygen-com/hyperframes without the owner saying "ยิง".
- Must not: commit/push directly to main.

## Judgment rules for cases not covered here
- Prefer adding a layer (skills, presets, scripts that wrap HyperFrames) over patching HyperFrames internals. If a Thai fix truly needs a change inside HyperFrames, stop and ask: fork vs upstream PR is the owner's call.
- Prefer fonts with an open license that ship via npm (e.g. @fontsource) so installs work offline-of-Google and are license-clean.
- When a Thai behavior can't be verified on this machine (e.g. TTS quality), mark it unverified in the README rather than claiming it works.
- If a URL can't be captured, follow HyperFrames' hard-stop rule; do not invent page content.

## Open questions
- Where the repo lives (Paneet GitHub org name) and when it goes public — owner decides at "ยิง".
- Which Thai TTS provider to recommend as default — quality untested.
- README language: Thai-first, English-first, or both.
- Whether the นกโหร film is used as the demo video.

## Tasks
1. Scaffold `url-to-ads` as a skill pack that installs alongside HyperFrames skills and routes "make an ad from this URL" requests — serves D2, D3, D5
2. Thai font layer: a Thai font pairing for each of the 13 presets (display + body), wired so Thai text never falls back to a random system font — serves D4
3. Thai captions: Thai word segmentation, sentence breaks without Latin punctuation, and a brand-name dictionary so names are never split across caption groups — serves D4
4. Thai narration via the user's own key, with word timings for captions; with no key, produce a silent + on-screen-text version instead of failing — serves D1, D4
5. Thai ad-copy guidance for the script step: tone, length per beat, and a reminder that health/beauty/food claims fall under อย./สคบ. rules — serves D4
6. End-to-end test on a Thai URL from a machine with open internet (e.g. https://nokhora.com/): deliver the MP4 + contact sheet, and list every Thai defect still visible — serves D4 (verification)
7. README with install steps for Claude Code / Codex / Cursor, BYOK setup, and what is verified vs not — serves D1, D5

Rule for the executor: if you hit a fork this brief does not cover, stop and ask. Do not guess.

Addendum to the brief (audio licensing):
- Constraint: every audio asset in a generated ad must be cleared for commercial use. The no-login offline music fallback in HyperFrames is MusicGen (facebook/musicgen-small), whose weights are CC-BY-NC 4.0 — non-commercial. Never use it for this tool.
- Music with no login: synthesize the score procedurally in code (oscillators / Karplus-Strong / filtered noise on a beat grid) so the output is fully owned. Lyria (user's Gemini key) only after confirming Google's terms allow commercial use of its output — if unconfirmed, stop and ask.
- SFX: the bundled 21-file Pixabay library is fine (Pixabay Content License allows commercial use).
- README must state the license source of each audio route.

Addendum (owner, 4 Oct 2026 — no keys):
- Owner: "อันไหนที่ต้องใช้ key ตัดออกเลย" — remove every route that needs an API key or account sign-in. Overrides the BYOK part of D1 and of tasks 4 and 7.
